# 旅行攻略景点配图规范

当用户要求景点参考图、图库、图文攻略或带图片的静态部署产物时，完整执行本规范。

## 覆盖范围

- 为每条方案的主要景点提供图片；餐厅、酒店和普通交通节点不默认配图。
- 以景点时间表和逐日行程的交集为核心，避免给同一路线上每个重复提及点重复下载。
- 组合项可以共用一张图，但标题必须准确说明图中实际地点。例如图片只拍到南屿时，不能直接声称它是金銮湾；可写“东山岛海岸（南屿）”并说明仅供海岸风格参考。
- 同一景点在主方案和备选方案重复出现时复用同一文件。

## 来源顺序与真实性

按以下顺序选图：

1. 用户提供并授权用于页面的图片。
2. Wikimedia Commons、政府开放图库或其他许可清晰、可追溯作者和授权条款的图片。
3. 景区、博物馆、文旅部门的官方图集；先确认页面或素材的使用条款。
4. 可靠旅行平台的具体景点页，仅在用户明确需要参考图且前述来源没有精确图片时使用，并保留来源页链接。

不要从小红书笔记、个人游记或社交媒体直接下载并再发布作者照片，除非用户提供素材或取得授权。不要把 AI 生成图作为真实景点参考图；用户明确要求概念图时，必须标注“AI 生成示意图”。

每张图在写入页面前核对：画面主体、城市/景点、拍摄方向（若涉及机位）、来源页标题与文件说明。图片搜索结果的自动描述只能作为候选线索，不能代替核对。发现错景、营销拼图、大字水印、严重拉伸或低清时更换。

## 下载、压缩与目录

- 将最终图片下载为本地静态资源，默认路径 `images/attractions/{slug}.webp`；在 Vite 等构建项目中可放入 `public/images/attractions/`。
- 使用稳定的小写英文 slug；不要把中文、查询串、作者隐私信息或临时 token 写入文件名。
- 长边建议 960–1280 像素，WebP 质量约 72–82；优先控制单图在 60–220 KB，保留足够的建筑与地貌细节。
- 不放大低分辨率原图，不把纵图强行裁成横图文件；页面使用固定 `aspect-ratio` 和 `object-fit: cover` 统一卡片视觉。
- 页面使用相对路径，不使用 `file://`、临时签名 URL、搜索结果缓存 URL或运行时接口请求。
- 构建后检查所有引用均存在，再把入口 HTML 与完整图片目录一起打包；ZIP 根目录直接包含 `index.html`，避免多套一层目录。

## 页面卡片

推荐在每条方案的景点时间表后放置 2–3 列响应式图库：

```html
<figure class="attraction-card">
  <a class="image-link" href="{source-page}">
    <img src="images/attractions/{slug}.webp"
         alt="{可感知画面主体与准确地点}"
         loading="lazy" width="960" height="640">
  </a>
  <figcaption>
    <strong>{景点名}</strong>
    <span>{一句景观或体验说明}</span>
    <small>{作者 · 许可或来源机构}</small>
  </figcaption>
</figure>
```

- `alt` 描述画面，不堆砌关键词；不能只写“景点图片”。
- 首屏以外使用 `loading="lazy"`；已知尺寸时写 `width`、`height` 或通过 CSS 预留比例，减少布局跳动。
- 点击图片打开来源页，而不是裸图片地址，方便用户核对作者、许可和更多说明。
- 图注说明图片与行程的关系。花期、秋色、积雪、日出日落、潮汐和演出场景存在不确定性时，紧邻图库提示“仅作景观参考，以出行日现场为准”。
- 移动端改为单列；图片卡片和图注打印时避免拆页。

## 来源记录

至少记录：景点名、本地文件、来源页 URL、作者/机构、许可（可取得时）、是否为同区域参考图。可在图注直接展示，也可在页面来源区集中列出；不得只保留无法追溯的图片直链。

Wikimedia Commons 图片遵守对应文件页许可，保留作者和许可名称；若许可要求署名或相同方式共享，不得删除这些信息。来源页未给出开放许可时，不声称图片可自由商用。

## 回退规则

- 找不到精确且可合法复用的实景图：保留带景点名、简述和官方图集链接的无图卡，不用无关地区照片顶替。
- 只有同一区域参考图：明确标注“同区域景观参考”，并在 `alt` 和图注中写实际画面地点。
- 图片下载或转换失败：最多换一个可靠来源重试一次；仍失败则使用无图卡，不留下断链或空白占位。
- 构建后发现图片缺失、尺寸为零或格式无法解码：视为交付失败，修复后重新构建和打包。

## 验证清单

- 每个主要景点都有对应卡片，重复景点没有重复资源。
- 图片实际内容、标题、`alt` 和来源页一致。
- 页面无外部图片依赖，无断链；本地打开和构建产物都能加载。
- 桌面 3 列、平板 2 列、手机 1 列；裁切不遮掉核心主体。
- 所有图片均为 WebP 或浏览器稳定支持的格式，文件体积合理。
- 版权/来源和季节差异提示可见；生成图没有伪装成现场图。
