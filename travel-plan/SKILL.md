# travel-plan — 旅行规划与攻略细化

这是完整、可独立运行的旅行规划 skill。它包含 Travel Planner 的需求确认、双轮研究、路线规划、HTML 生成、预算与行前准备能力，并增加多方案完整比较、车次核验、餐厅分店与营业时间、每个住宿地 2–3 家酒店及优缺点等执行层细节。

依赖 `$x-mcp` 获取小红书笔记和评论区反馈；公开网络用于核验官方或预订平台信息。x-mcp 的安装、登录或连接说明以 [xpzouying/x-mcp](https://github.com/xpzouying/x-mcp) 为准。

## 版本检查

每次使用本 skill 时，在开始旅行规划前执行一次非阻塞版本检查：

1. 读取本 skill 目录中的 `VERSION`，作为本地版本。
2. 获取 GitHub `main` 分支的 `https://raw.githubusercontent.com/hienao/MySkills/main/travel-plan/VERSION`，作为最新版本。
3. 将两者按语义版本号比较。只有远端版本高于本地版本时，才简短提示用户：当前版本、最新版本、更新地址 `https://github.com/hienao/MySkills`，以及更新方式。
4. 如果当前 skill 位于 Git 仓库或通过软链接指向 Git 仓库，更新方式提示为在对应仓库执行 `git pull --ff-only`；如果是复制安装，则提示重新下载并替换 `travel-plan` 目录。
5. 不自动更新、不覆盖本地文件，也不因发现新版而中断当前旅行任务。
6. 如果网络不可用、远端文件不存在、内容不是有效版本号或检查异常，静默跳过并继续任务；不要声称本地是最新版。

版本格式固定为不带 `v` 前缀的三段式语义版本，例如 `1.0.0`。

## 工作模式

根据请求选择一种模式，但使用相同的数据质量标准：

- **从零规划**：用户提供目的地或候选列表，研究并生成完整攻略。
- **多方案比较**：所有候选方案先统一评分，再给首选组合；每条备选仍需完整可执行。
- **细化现有攻略**：保留原文件风格和已有正确内容，补交通、餐厅、酒店、价格、营业时间、预算与来源。

## Phase 1：确认需求

从对话、附件或现有攻略中提取以下信息；已提供的不要重复询问：

1. 目的地或候选目的地。
2. 出发地、出行日期、天数和晚数。
3. 高铁、飞机、自驾、房车或综合比价偏好。
4. 同行人数，以及老人、儿童或行动限制。
5. 自然、人文、美食、亲子、摄影等侧重。
6. 预算范围和住宿档次。

只有缺失信息会实质改变路线时才提问；确认后自动继续，不在每个阶段反复等待用户。

先校验日期口径。`5 天 4 晚` 对应 5 个自然日；如果日期范围与天数冲突，明确采用哪个口径，不静默增加或减少一天。

## Phase 2：信息研究

研究分两轮进行：小红书优先，公开搜索核验。

### 第一轮：使用 x-mcp 深挖小红书

每次创建新攻略或新增目的地时都重新尝试，不因上次超时而跳过：

1. 调用 `check_login_status`。
2. 未登录时停止小红书调研，明确告知用户打开 [xpzouying/x-mcp](https://github.com/xpzouying/x-mcp)，参考仓库说明安装或添加 MCP、配置连接并完成小红书登录；不要只笼统提示“请登录”。用户处理完成后再重新检查。
3. 每个目的地至少搜索以下维度：
   - `{目的地} 攻略 {天数}天`
   - `{目的地} 避坑 踩雷`
   - `{目的地} 费用 花费 预算`
   - `{目的地} 住宿 酒店推荐`
   - `{目的地} 美食 餐厅`
   - 摄影需求明显时，再搜 `{目的地} 拍照 机位 时间`
4. 对相关度、收藏和讨论质量较高的 3–5 篇调用 `get_feed_detail`，阅读正文及评论区。
5. 提取实付价格、路线耗时、住宿缺点、排队、交通不便、隐形消费、季节变化和评论区纠错。
6. 记录作者、笔记 ID 和链接，供攻略来源区引用。

单次搜索超时时至少换短关键词重试两次。若 `$x-mcp` 工具未安装、连接异常、登录检查报错、持续超时或其他原因不可用，停止小红书调研，说明具体异常，并告知用户打开 [xpzouying/x-mcp](https://github.com/xpzouying/x-mcp) 按说明添加和排查 MCP。只有用户明确选择跳过后，才改用公开网络继续，并标注“小红书实测未核验”。

### 第二轮：公开网络核验

优先官方和一手来源，预订平台用于价格、地址和住客点评：

- **交通**：铁路车次、车站、时间、票价、预售期；航班、行李额、机场接驳和门到门成本；自驾距离、停车和路况。
- **景点**：开放时间、停止入场、门票、预约周期、闭馆日、季节性调整和游览时长。
- **餐厅**：准确分店、地址、营业时段、招牌菜、排队和临时休息风险。
- **酒店**：区域、每晚价格、交通位置、房型、早餐、取消政策、停车、电梯、隔音、洗衣和近期维护评价。
- **实用信息**：天气、潮汐、海况、温差、当地交通、预约渠道和携带物品。
- **预算**：大交通、酒店、门票、餐饮、当地交通、保险、通讯和机动费用。

信息融合优先级：

- 实际花费：近期真实订单/体验 > 同日期平台标价 > 攻略估算。
- 避坑：近期评论区 > 笔记正文 > 泛攻略文章。
- 开放和规则：官方公告 > 政府或权威媒体 > 预订平台 > 个人内容。
- 路线：高质量实测反馈与地理、交通事实共同决定。

无法确认的信息使用“约、常规、以当天公告为准”等限定，不编造精确值。

## Phase 3：比较和路线规划

### 多方案决策

按用户条件统一比较：景色/人文/美食、轻松度、交通时间、门到门成本、天气风险、换酒店次数和天数适配度。说明评分只针对本次日期和偏好，不是目的地的绝对排名。

给出一个首选和必要的替代项。若组合两个城市，必须证明跨城交通、住宿基地和时间成本合理，不为丰富度硬拼目的地。

### 每条方案都要完整

每个方案至少包含：

- 适合人群、优势、短板和关键取舍。
- 推荐交通方式；高铁/飞机/自驾备选、具体班次样本、时间和成本。
- 按天的主题、时间段、3–5 个景点或活动、用餐和住宿。
- 景点开放/停止入场时间、门票、预约及闭馆日。
- 顺路餐厅的准确分店、地址、营业时间、建议菜品和避坑。
- 每个实际过夜地点 2–3 家酒店及价格、位置、优点、缺点和适合人群。
- 用户指定人数的经济、舒适和宽松预算。
- 天气、闭馆、停航、延误等 B 计划，以及出发前复核节点。

路线按地理位置和主题分段。每天标出建议时间段、交通缓冲、午休和 3–5 个亮点。尊重“不爬山、少步行、亲子、老人”等限制，不用景点名义上平缓来掩盖长距离步行或连续台阶。

控制换酒店次数：五天四晚通常使用 1–2 个住宿基地；只有公路环线等确有必要时才每天换住。

## 交通数据规则

- 日期已开售时，核验用户实际日期的班次和票价。
- 日期未进入铁路预售期时，只能写“当前运行图样本”，同时给预计开售日和最终以 12306 为准的提醒。
- 飞机与高铁同时列出门到门时间，包含提前到机场、行李、机场到市区和跨城接驳。
- 给出可执行的价格阈值，例如“机票比高铁贵不超过某金额时优先飞机”，而不是只列两个价格。
- 不推荐需要极端早起、压缩景点或高风险转乘的纸面最短路线。

## 酒店选择标准

每个实际过夜地点列 2–3 家，覆盖至少两种取向：位置/稳定性首选、性价比、景观或高端体验。

统一价格口径：指定日期、1 间 2 成人、相近房型、同早餐、税费和取消政策。价格写成“规划区间/间夜”，标注查询日期；不把平台最低展示价当成可订成交价。

优缺点必须具体：

- 到景点、餐厅、车站或机场的实际衔接。
- 是否适合拖行李、早出发、晚归或停车。
- 新旧程度、隔音、电梯、洗衣、早餐、房间面积和民宿房型差异。
- 海景/景观房溢价是否值得，周末涨价和团队客风险。

提醒用户优先锁定可免费取消房型，在出发前 7–10 天按相同条件复查含税总价。

## Phase 4：生成或更新 HTML

需要 HTML 时，必须先完整阅读 [references/html-spec.md](references/html-spec.md)，再生成页面。

文件名默认 `{目的地拼音}_travel_guide.html`；多目的地比较可用 `{出发地拼音}_trip_comparison.html`。保存到用户工作目录。

页面内容建议顺序：

1. Hero 与决策摘要。
2. 快速跳转。
3. 方案比较与首选理由。
4. 路线总览和交通方案。
5. 首选逐日攻略。
6. 每条完整备选攻略。
7. 酒店、景点与餐厅明细。
8. 三档预算。
9. 预约、天气 B 计划与最后检查。
10. 小红书体验来源和官方/平台核验来源。

所有数据硬编码进单文件 HTML，不依赖外部 CSS、JavaScript 或图片。生成后在浏览器中预览，检查桌面与窄屏布局、锚点、长表格和打印效果；修复日期、闭馆日和交通衔接矛盾后再交付。

## 预算规则

按用户人数和天数计算：大交通、酒店、景点门票、餐饮、当地交通、保险/签证（如有）、其他与机动费用。分别给经济型、舒适型和宽松型总计，并指出最大价格变量。

酒店小计必须与推荐酒店的间夜区间一致；不要出现酒店表写高价、总预算却按低价计算的矛盾。

## 交付与复核

最终答复先给推荐结论，再给可点击的 HTML 或文件路径。明确说明：

- 哪些车次是当前运行图样本。
- 哪些价格不是锁价。
- 车票预计开售日、酒店复价日和景区/餐厅最终核验日。
- 小红书用于真实体验，官方或预订平台用于规则和时效核验。

不要声称已订票、订房或预约，除非用户明确授权且实际完成。
